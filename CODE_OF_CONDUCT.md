# Code of conduct

## The short version

Be decent to people. Assume they are acting in good faith. Argue about the work,
not the person doing it.

## What is expected

- **Engage with the substance.** Disagreement is useful; contempt is not. "This
  breaks offline writes because…" is a review. "This is amateur" is not.
- **Assume competence and good faith.** People come from different stacks and
  different levels of context. A question is not an attack, and a mistake is not
  a character flaw.
- **Accept that maintainers say no.** A rejected pull request usually means the
  change conflicts with a constraint you could not have known about. Ask which
  one; that answer belongs in the documentation if it is not there already.
- **Respect people's privacy.** This project handles training, nutrition, and
  health data. Never post someone's real data in an issue, and never ask for it —
  a reproduction needs the shape of the data, not the contents.

## What is not acceptable

- Harassment, intimidation, or discrimination based on who someone is.
- Sexual attention or imagery. This is a training log, not a venue for it.
- Publishing someone's private information without their explicit permission.
- Sustained disruption: derailing threads, relitigating settled decisions without
  new information, or demanding unpaid attention.

## Scope

This applies in the repository — issues, pull requests, discussions, commit
messages, code comments — and anywhere someone is representing the project.

## Reporting

Report a problem privately through the **Security** tab's
[private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability),
which opens a report visible only to the maintainers. It is not only for security
issues, and it is the most private channel available here.

Reports are handled confidentially. You will not be asked to justify why
something bothered you, and reporting in good faith will never count against you,
whatever the outcome.

## Enforcement

Depending on severity: a private word, a public correction, temporary exclusion
from a thread, or a permanent block. Maintainers who break this document are held
to it more firmly than anyone else, not less.
